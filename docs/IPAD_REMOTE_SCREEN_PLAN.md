# แผนพัฒนา: iPad เป็นจอลูกค้า + PC เป็นตัวพิมพ์ (ฟรี)

สถานะ: ขั้น 1–3 และการ์ดแอดมินเขียนเสร็จ รอทดสอบกับ iPad จริง · 2026-10-28
ทางเลือกนี้ไม่ต้องทำแอป iPad และไม่ต้องมีบัญชี Apple Developer (ดูทางเลือกแบบแอป iPad ใน `docs/IPAD_PLAN.md`)

## ทำแล้ว

| ส่วน | ไฟล์ | ตรวจแล้ว |
|---|---|---|
| ฟิลเตอร์รูปใช้ได้บน Safari (ปรับพิกเซลเมื่อ `ctx.filter` ใช้ไม่ได้) | `public/css-filter.js`, `public/shared.js`, `processing.html` | เทสต์ 5 ข้อ + WebKit: เปิดทุกหน้า 14 หน้าไม่มี error, ฟิลเตอร์ขาวดำออกเป็นสีเทาจริง |
| ใบรับรองที่ PC สร้างเอง (CA + HTTPS, ECDSA P-256, 800 วัน, SAN ชื่อ/IP) | `agent/certs.mjs` | เทสต์ 5 ข้อ + OpenSSL ยืนยัน chain/ชื่อ/IP/serverAuth |
| เซิร์ฟเวอร์ให้ iPad: HTTPS 8443 + HTTP 8080 (เฉพาะใบรับรอง), รับเฉพาะวงภายใน, ตรวจ Host, จับคู่ด้วยรหัส 6 หลักใช้ครั้งเดียว 5 นาที, คุกกี้ต่อเครื่อง (เก็บแค่ hash), ยกเลิกได้ | `agent/remote-screen.mjs` | เทสต์ 12 ข้อ (รวมยิง HTTPS จริง) |
| สิทธิ์ PIN แอดมินแยกต่อจอ | `bridge/core.mjs`, `agent/server.mjs` | ทดสอบ agent จริงแบบ end-to-end 9 ข้อผ่าน |
| เปิด/ปิด, QR ติดตั้งใบรับรอง, QR จับคู่, รายการ iPad + ยกเลิก (จัดการได้จากจอ PC + PIN เท่านั้น) | `admin.html` | ตรวจหน้าตาการ์ดในเบราว์เซอร์ |

ยังไม่ทำ: Dashboard แสดงสถานะ iPad (ต้องแก้ตารางใน Supabase), โหมด "จอ PC แสดงว่าใช้งานที่ iPad"

## ทดสอบกับ iPad จริง

1. ติดตั้งโปรแกรมตู้เวอร์ชันนี้บน PC (ผ่านช่องอัปเดตทดลอง `npm run publish:update` หรือตัวติดตั้งใหม่)
2. PC: หน้าแอดมิน → ใส่ PIN → การ์ด **เชื่อมต่อ iPad** → **เปิดให้ iPad ใช้งาน** (ถ้า Windows ถามไฟร์วอลล์ กด "อนุญาต" เครือข่ายส่วนตัว)
3. iPad (Safari): สแกน QR ช่อง 1 → ดาวน์โหลดใบรับรอง → การตั้งค่า → ติดตั้งโปรไฟล์ → ทั่วไป → เกี่ยวกับ → การตั้งค่าความเชื่อถือใบรับรอง → เปิดสวิตช์
4. PC: กด **สร้าง QR จับคู่** → iPad สแกน → เข้าหน้าแรกของตู้
5. iPad: แชร์ → เพิ่มลงหน้าจอโฮม → เปิดจากไอคอน (เต็มจอ) → ทดสอบตามเช็กลิสต์ด้านล่าง

## เป้าหมาย

- ลูกค้าใช้ **iPad** (Safari เต็มจอ) ทุกขั้นตอน: เลือกเลย์เอาต์, ถ่ายด้วยกล้อง iPad, เลือกธีม/ฟิลเตอร์, Redeem/PromptPay, QR ดาวน์โหลด
- **PC ที่ลงโปรแกรมตู้ Windows** (agent) เป็นตัวกลาง: ถือ credential, ตัดสิทธิ์, พิมพ์ออกเครื่องพิมพ์ที่ต่อกับ PC ทันที ไม่มีหน้าต่างพิมพ์
- ฟรี, ใช้ระบบเดิม (สิทธิ์พิมพ์, กันพิมพ์ซ้ำ, Dashboard, อัปเดตอัตโนมัติ) ทั้งหมด
- ปลอดภัย: เฉพาะ iPad ที่จับคู่แล้วเท่านั้นที่สั่งงานได้ แม้มีคนอื่นต่อ Wi-Fi ร้าน

## ภาพรวม

```
iPad (Safari, เพิ่มลงหน้าจอหลัก + Guided Access)
   │  https://<ชื่อคอม>.local:8443   ← ใบรับรองที่ PC สร้างเอง (ติดตั้งบน iPad ครั้งเดียว)
   │  คุกกี้จับคู่ (pairing) ทุกคำขอ
   ▼
PC: agent/server.mjs
   ├─ 127.0.0.1:8787  (เดิม: จอของ PC เอง)
   ├─ 0.0.0.0:8443    (ใหม่: HTTPS ให้ iPad, ต้องจับคู่)
   ├─ 0.0.0.0:8080    (ใหม่: HTTP เฉพาะหน้าดาวน์โหลดใบรับรองและวิธีติดตั้ง)
   └─ เครื่องพิมพ์ USB/LAN ของ PC (ESC/POS raw หรือไดรเวอร์ Windows ตามเดิม)
```

หน้าเว็บที่ iPad เปิดคือ `dist-next` ชุดเดียวกันที่ agent เสิร์ฟอยู่แล้ว และ agent แทรก `/__bridge.js` ให้ทุกหน้าเหมือนเดิม จึงได้ `window.PhotoboothDevice` / `PhotoboothPrinter` ครบทุกเมธอดโดยไม่ต้องเขียนใหม่

## สิ่งที่ต้องพัฒนา

### ขั้น 1 — หน้าเว็บใช้กับ Safari ได้ (ทำได้ทันที, ทุกตู้ได้ประโยชน์)

| งาน | รายละเอียด |
|---|---|
| ฟิลเตอร์รูป | `applyPhotosFilter` ใน `public/shared.js` ใช้ `ctx.filter` ซึ่ง Safari ไม่รองรับ → รูปไม่ติดฟิลเตอร์ เปลี่ยนเป็นคำนวณพิกเซลเอง (grayscale/sepia/contrast/brightness/saturate) ให้ผลตรงกับเดิม และใช้ทางเดิมเมื่อเบราว์เซอร์รองรับ |
| ตรวจทุกหน้าด้วย WebKit | ใช้ Playwright WebKit (รันบน Windows ได้, ฟรี) เปิดทุกหน้า: home, layout, capture (กล้องจำลอง), template, filter, processing (GIF), print, admin, studio — หา error และสิ่งที่แสดงผิด |
| เทสต์ | เทสต์ฟิลเตอร์แบบพิกเซลเทียบกับผลจาก Chrome |

### ขั้น 2 — agent เปิดให้ iPad เข้าผ่าน Wi-Fi แบบ HTTPS

| งาน | รายละเอียด |
|---|---|
| เปิด/ปิดได้ | ค่าใหม่ใน config `remoteScreen: { enabled }` ค่าเริ่มต้น **ปิด** ตู้เดิมไม่เปลี่ยนพฤติกรรมจนกว่าจะเปิดในแอดมิน |
| ใบรับรอง (ฟรี) | ครั้งแรกที่เปิด: สร้าง CA ประจำเครื่อง + ใบรับรองเซิร์ฟเวอร์ด้วย PowerShell `New-SelfSignedCertificate` (มีใน Windows) ใส่ชื่อ `<ชื่อคอม>.local` และ IP ปัจจุบันใน SAN, อายุ ≤ 825 วันตามกฎของ Apple, เก็บเป็น PFX ใน `data/` (รหัสผ่าน PFX เข้ารหัสด้วย DPAPI แบบเดียวกับ credential) |
| เซิร์ฟเวอร์ HTTPS | `https.createServer({ pfx })` ที่พอร์ต 8443 ใช้ตัวจัดการคำขอเดียวกับ 8787 (แยกฟังก์ชัน handler ออกมาใช้ร่วม) |
| หน้าติดตั้งใบรับรอง | HTTP พอร์ต 8080 เสิร์ฟเฉพาะ `/` (วิธีติดตั้งภาษาไทยพร้อมรูป) และ `/ca.cer` — ไม่มีอย่างอื่นบน HTTP |
| กันคนนอก | รับเฉพาะ IP วงภายใน (192.168/10/172.16–31), ตรวจ Host เป็นชื่อคอม/IP ของเครื่อง, ต้องมีคุกกี้จับคู่ทุกคำขอ (ยกเว้นหน้าจับคู่) |
| IP เปลี่ยน | ใช้ชื่อ `<ชื่อคอม>.local` เป็นหลัก (iPad หาเจอเองผ่าน mDNS) และสร้างใบรับรองใหม่อัตโนมัติเมื่อ IP เปลี่ยน; แนะนำตั้ง IP คงที่ให้ PC ที่เราเตอร์ |
| Firewall | ตัวติดตั้งไม่ใช้สิทธิ์ผู้ดูแล จึงเพิ่มกฎเองไม่ได้: ครั้งแรกที่เปิด Windows จะถามอนุญาต (ต้องกด "อนุญาต" สำหรับเครือข่าย **ส่วนตัว** หนึ่งครั้ง) และหน้าแอดมินมีปุ่มตรวจว่า iPad เข้าถึงได้หรือยัง |

### ขั้น 3 — จับคู่ iPad และแยกสิทธิ์ต่อจอ

| งาน | รายละเอียด |
|---|---|
| จับคู่ด้วย QR | หน้าแอดมินบน PC: "เชื่อมต่อ iPad" → ขั้นที่ 1 QR ไปหน้าติดตั้งใบรับรอง, ขั้นที่ 2 QR `https://<ชื่อคอม>.local:8443/pair?code=XXXXXX` (ใช้ได้ครั้งเดียว, 5 นาที) |
| คุกกี้ | จับคู่สำเร็จ → คุกกี้ `HttpOnly; Secure; SameSite=Strict` สุ่ม 256 บิต เก็บ hash ใน config (อยู่ได้จนกว่าจะยกเลิก), จำกัดจำนวนครั้งที่ใส่รหัสผิด |
| ยกเลิก iPad | หน้าแอดมินแสดงรายการ iPad ที่จับคู่ + ปุ่มยกเลิก |
| **แยก PIN แอดมินต่อจอ** | ตอนนี้ `bridge/core.mjs` เก็บสิทธิ์แอดมินไว้ตัวเดียวทั้งโปรแกรม ถ้าใส่ PIN ที่ PC แล้ว iPad จะได้สิทธิ์แอดมินด้วย → เปลี่ยนให้สิทธิ์แอดมินผูกกับจอที่ใส่ PIN (คุกกี้/รหัสจอ) |
| จอหลักจอเดียว | ตั้งค่า "จอลูกค้า = iPad": จอ PC แสดง "ใช้งานที่ iPad" + สถานะเครื่องพิมพ์ (กันลูกค้าสองคนใช้พร้อมกันซึ่งระบบไม่ได้ออกแบบไว้) |

### ขั้น 4 — ใช้งานจริงบน iPad

| งาน | รายละเอียด |
|---|---|
| เต็มจอ | Safari → แชร์ → "เพิ่มลงหน้าจอโฮม" (มี `manifest.json` แบบ standalone + แนวตั้งอยู่แล้ว) |
| ล็อกจอ | Guided Access (ฟรี): การตั้งค่า → การช่วยการเข้าถึง → การเข้าถึงที่แนะนำ |
| จอไม่ดับ | การตั้งค่า → จอภาพ → ล็อกอัตโนมัติ = ไม่ใช้, และหน้าเว็บขอ Screen Wake Lock อยู่แล้ว |
| กล้อง | Safari ถามสิทธิ์กล้อง → อนุญาต (ตั้งเป็น "อนุญาต" ถาวรสำหรับเว็บนี้ได้) |
| Dashboard | heartbeat รายงานเพิ่ม: iPad ต่ออยู่ไหม, เห็นครั้งล่าสุดเมื่อไร |
| อัปเดต | iPad รีโหลดเองเมื่อ PC อัปเดตเวอร์ชันใหม่ (กลไกเดิมใน `clientScript`) ไม่ต้องทำอะไรเพิ่ม |

### ขั้น 5 — ทดสอบและปล่อย

- เทสต์อัตโนมัติ: จับคู่/ยกเลิก, ปฏิเสธคำขอไม่มีคุกกี้, ปฏิเสธ IP นอกวง, แยก PIN แอดมินต่อจอ, direct-print โหมด Event ต้องจับคู่
- ทดสอบกับ iPad จริง (เช็กลิสต์ด้านล่าง)
- ปล่อยผ่านช่องอัปเดตเดิม: `npm run publish:update` (ทดลองที่เครื่องหลัก) → `npm run promote:update`

## สิ่งที่ต้องเตรียม (ทั้งหมดฟรี)

- iPad ที่ใช้ iPadOS 16.4 ขึ้นไป (แนะนำ 17+) กับ PC อยู่ Wi-Fi วงเดียวกัน
- PC เปิดค้างไว้ตลอดเวลาทำการ (โปรแกรมตู้ทำให้ไม่หลับอยู่แล้ว)
- ตั้ง IP คงที่ให้ PC ที่เราเตอร์ (แนะนำ ไม่บังคับ)
- ครั้งแรก: กดอนุญาต Windows Firewall หนึ่งครั้ง และติดตั้งใบรับรองบน iPad หนึ่งครั้ง

## ความเสี่ยงและวิธีรับมือ

| ความเสี่ยง | วิธีรับมือ |
|---|---|
| Wi-Fi ร้านไม่เสถียร → iPad หลุดระหว่างใช้ | ตรรกะสิทธิ์พิมพ์เดิมกันพิมพ์ซ้ำ/ตัดสิทธิ์ผิดอยู่แล้ว; แนะนำเราเตอร์แยกสำหรับตู้ |
| เราเตอร์บางตัวบล็อกเครื่องคุยกันเอง (AP/client isolation, Wi-Fi แขก) | หน้าแอดมินตรวจการเข้าถึงและบอกให้ปิด isolation หรือใช้ Wi-Fi หลัก |
| `<ชื่อคอม>.local` ไม่เจอในบางเครือข่าย | QR ใส่ทั้งชื่อและ IP; ใบรับรองมีทั้งสองแบบ |
| ภาพ/GIF ช้าบน iPad รุ่นเก่า | ทดสอบรุ่นที่ใช้จริง; ลดขนาดภาพระหว่างประมวลผลถ้าจำเป็น |
| เปิดพอร์ตบน PC เพิ่มช่องให้ถูกโจมตี | ค่าเริ่มต้นปิด, รับเฉพาะวงภายใน, ต้องจับคู่ทุกคำขอ, credential ไม่เคยออกจาก PC |

## ลำดับและขนาดงานโดยประมาณ

| ขั้น | ขนาดงาน | ทดสอบได้เมื่อ |
|---|---|---|
| 1 Safari compatibility | เล็ก | ทันที (WebKit บน Windows) |
| 2 HTTPS ใน Wi-Fi | กลาง | มี iPad + PC วงเดียวกัน |
| 3 จับคู่ + แยก PIN ต่อจอ | กลาง | หลังขั้น 2 |
| 4 ตั้งค่า iPad + Dashboard | เล็ก | หลังขั้น 3 |
| 5 ทดสอบ + ปล่อย | เล็ก | หลังขั้น 4 |

ขั้น 1 ทำและส่งทดสอบแยกได้ก่อน; ขั้น 2–4 ส่งทดสอบรวมเป็นตัวติดตั้ง/อัปเดตเดียว (ผ่านช่องทดลองก่อน)
